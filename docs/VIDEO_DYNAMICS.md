# 🎞 Анализ динамики видео — инструкция

Одна и та же кнопка **🎞 Анализ динамики видео** доступна из двух мест и
ведёт в одно и то же:
- **Генерация → 🎬 Видео**
- **🕵️ Исследование и поиск человека (OSINT)**

## Что делает
Кидаешь видео — бот делает **два прохода**:

### 1. Детальный проход (кадр за кадром)
- Нарезает **много скриншотов** с шагом **0.5–5 секунд** (настраивается),
  в низком качестве, но различимо — чтобы видно было, что меняется в кадре.
- Разбирает **каждый** скрин через Vision: ракурс/план камеры, что в кадре,
  какое действие.
- На каждый кадр пишет **промт для воспроизведения** (англоязычный image-промт).
- Складывает это в рассказ про **динамику ракурса** (как движется камера) и
  **последовательность экшна** (что происходит по шагам).

### 2. Проход-проверка (каждые ~5 секунд)
Параллельно бот сэмплирует кадры с большим шагом (по умолчанию **5с**,
настраивается) и для каждого считает **CV-метрики без нейронки**:
- `motion` — насколько кадр изменился относительно предыдущего сэмпла
  (mean abs diff по серому);
- `sharp` — резкость (variance of Laplacian); низкая = кадр смазан.

Вердикт на каждый сегмент:
| motion | sharp | вывод |
|--------|-------|-------|
| высокий | высокий | ✅ реальная динамика |
| высокий | низкий | ⚠️ движение есть, но кадр смазан (motion blur) |
| низкий | низкий | 🟡 **смаз без реальной динамики** (размыто, но сцена не меняется) |
| низкий | высокий | ⏸ статика |
| средний | — | 〽️ слабая динамика |

Это решает задачу «а вдруг скрин просто размазан в движении, а динамики на
самом деле нет»: если между сэмплами раз в 5с сцена почти не меняется —
значит реальной динамики нет, даже если отдельный кадр выглядит смазанным.

## Настройки
На экране фичи две строки кнопок:
- **Детальный шаг**: 0.5 / 1 / 2 / 3 / 5 с
- **Шаг проверки**: 5 / 10 / 15 / 30 с

## Где в коде
- Логика: `bot/addons/viddyn/analyzer.py` (cv2-нарезка + метрики, Vision-разбор
  через `groq_helpers.describe_image_with_groq`, синтез через
  `agent.oneshot_summary`), настройки `bot/addons/viddyn/store.py`.
- UI/хендлеры на `wizard_router` (состояние `VidDynStates.awaiting_video`):
  секция «🎞 Анализ динамики видео» в `bot/wizard.py`.
- Кнопки: `media_ui._kb_video_prompt` и `addons/osint/handlers._kb_home`,
  обе с `callback_data="viddyn:open"`.

Если Groq Vision не настроен — бот всё равно отдаёт CV-метрики динамики
(+ OCR), а описания кадров пропускает с пометкой.

# 🧰 GitHub-инструменты анализа видео (отдельная кнопка)

Кнопка **🧰 GitHub-инструменты анализа** доступна из **Генерация → 🎬 Видео**
и из **🕵️ Исследование (OSINT)** — ведёт в каталог тулзов для анализа
динамики/движения. У каждого инструмента: ссылка на GitHub + **сценарий
алгоритма** (последовательность действий).

## Лёгкие — гоняются прямо на видео (CPU, на хосте)
- 🌀 **Optical Flow (Farneback)** — реальное движение по пикселям. **Уже
  встроен** в «🎞 Анализ динамики видео» как основная метрика (peak flow в px).
- ✂️ **PySceneDetect** — точные смены сцен/кадров (ContentDetector).
- 🌫 **Blur detection** — variance-of-Laplacian, какие кадры смазаны.

Нажми инструмент → **▶️ Запустить на видео** → пришли видео → бот прогонит
алгоритм и вернёт результат (таймлайн по кадрам/сценам).

## Тяжёлые — GPU/большие модели (на Render-хосте не запустить)
- 🧠 byjlw/video-analyzer (Vision-LLM + Whisper → описание видео)
- 🎞 simonw/llm-video-frames (видео→кадры→любой Vision-LLM)
- 🎬 TransNetV2, 🎯 AutoShot (SOTA shot-boundary), 🏞 RAFT (SOTA optical flow)

Для них кнопка **📥 Клонировать репо + рецепт**: бот делает `git clone --depth 1`,
показывает что внутри (файлы, requirements) и сценарий запуска. Гонять их
нужно отдельно (GPU) или через внешний API-ключ.

## Где в коде
- Каталог: `bot/addons/ghtools/catalog.py` (`TOOLS`, `TOOLS_BY_KEY`).
- Раннеры: `bot/addons/ghtools/runner.py` (`run_on_video`, `clone_probe`).
- UI на `wizard_router` (состояние `GhToolsStates.awaiting_video`): секция
  «🧰 GitHub-инструменты» в `bot/wizard.py`; кнопки `ghtools:open` в
  `media_ui._kb_video_prompt` и `osint/handlers._kb_home`.
