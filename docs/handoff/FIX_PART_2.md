## Задача A — фикс 1.4: пагинация VK-клавиатуры (MUST, ТЗ §6)

Сейчас: `vk_gw.screen_to_vk_keyboard(screen) -> (keyboard, truncated)`
режет всё после лимита (10 inline-кнопок), лишние кнопки пропадают,
`_screen_text` дописывает предупреждение. Пользователь VK не может
добраться до части меню.

Сделать:

1. Новая сигнатура рендера (или новая функция рядом):
   `screen_to_vk_keyboard(screen, page=0)` — 5 рядов контента на
   страницу + 1 служебный ряд «⬅️ Назад | стр. N/M | ➡️ Вперёд»
   (служебный ряд только если страниц > 1). Уважать VK-лимиты:
   ≤ 10 кнопок, ≤ 5 кнопок в ряду.
2. Callback-действия пагинации: `gateway:page:<screen_id>:<n>`.
   Payload VK ограничен, callback ≤ 64 байта: если
   `len(action) > 64` — использовать короткую форму
   `gateway:page:<n>` и хранить текущий `screen_id` per-peer.
3. Состояние страницы per-peer: addon-state `gateway`, ключ
   `vk_page:<peer_id>` → `{"screen_id": ..., "page": n}`.
   Сбрасывать при переходе на ЛЮБОЙ другой экран (в
   `_reply_for_action` при рендере нового screen_id — page=0).
4. Обработку `gateway:page:...` добавить в `_extract_action` /
   `_reply_for_action` пути vk_gw (НЕ в общий dispatch — действие
   служебное, платформенное): достать сохранённый screen_id,
   перерендерить его builder'ом через
   `dispatch_action(<screen-open action>, ...)` либо повторным
   вызовом рендера последнего экрана; выбрать простейший путь,
   задокументировать в docstring.
5. Флаг `truncated` и предупреждение в `_screen_text` больше не
   нужны для многостраничных экранов — оставить только для
   патологии (один ряд шире 5 кнопок).

## Задача B — фикс 2.4: «чат с мозгом» из Discord/VK (SHOULD, ТЗ R3)

Свободный текст (не команда `!lilush ...`, не `/link`, не код
привязки) от ПРИВЯЗАННОГО пользователя должен уходить в тот же
пайплайн диалога, что и обычное сообщение в TG (мозг/LLM), а ответ —
обратно в Discord/VK.

1. Найди TG-пайплайн диалога: точка входа обработки свободного текста
   (см. `bot/wizard.py` / `bot/handlers.py` / addons — ищи, куда
   уходит обычное сообщение пользователя для ответа мозгом). Выдели
   ЧИСТУЮ функцию вида `async def ask_brain(user_id, text) -> str`
   если её нет — оберни существующий код, НЕ дублируя логику.
2. VK (`_handle_update` в vk_gw) и Discord (`on_message` в
   discord_gw):
   - привязан (`identity.resolve_user_id(platform, external_id)`) →
     `ask_brain(mapped_user_id, text)` → ответ в тот же чат;
     ошибки мозга → вежливый текст, в лог — без текста пользователя;
   - не привязан → подсказка про привязку (уже есть — не ломать).
3. Если после исследования решишь, что чат с мозгом корректнее
   отложить до этапа 5 (медиашина) — это допустимо ТЗ, но тогда
   обязательно: (а) аргументация в тексте ответа для интегратора,
   который запишет её в `AI_CHANGELOG.md`; (б) вместо молчания бот
   отвечает привязанному пользователю заглушкой «Диалог с мозгом
   подключается на этапе 5».
