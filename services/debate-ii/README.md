# Debate-II

Многодверный сервер ИИ-дебатов с управлением из Telegram. До **20 независимых дверей** (комнат), в каждой — до **5 дебатёров** (Lindy, Devin.ai через браузер, любые ИИ). Двери не пересекаются. Дебаты идут **эстафетой**: ИИ ходят по очереди по пункту и передают ход, а свободный ИИ берёт следующий пункт параллельно, чтобы не ждать. Бот владельца показывает живые события дебата и сам пингует Render, чтобы тот не засыпал.

## Как устроено

- **FastAPI-сервер** (`app.py`) — двери: создать / удалить / список, общий веб-UI.
- **Дебаты** (`debate.py`) — на каждую дверь: слоты, **кворум-гейт** (дебаты не стартуют, пока не наберётся нужное число), **relay-движок** (очередь ходов + параллельные пункты), **лента событий** для живых пушей.
- **Контейнеры** (`containers.py`) — у каждого дебатёра в каждой двери своя папка: `log.jsonl` + `summary.md` (личные «напоминалки») + свои файлы.
- **Telegram-бот** (`telegram_bot.py`) — пульт владельца на инлайн-кнопках. Сам в дебатах не участвует.

### Правила архитектуры

1. **Кнопочное меню:** `[🧠 Мозг] [🚪 Двери]`.
2. **Двери динамичны:** ➕ создаёт дверь и сразу выдаёт её ссылку; ✕ удаляет. Список живой — видно `x/y` подключений и идут ли дебаты.
3. **Своя ссылка у каждой двери** — `{server}/door/{id}`. Её даёшь ИИ + файл-тему (ТЗ) + число дебатёров.
4. **Кворум:** число дебатёров говорит участникам, когда начинать. Пока не набралось N — `say`/`contribute`/`round` отдают `425 Too Early`. Набралось — авто-старт.
5. **Один дебатёр — одна дверь.** Каждый Lindy (= один чат) в одной двери. Второй чат — другой Lindy.
6. **Двери не пересекаются** — полная изоляция состояния, контейнеров, архива.
7. **Владелец бота — первый, кто нажал `/start`** (его ID пишется на диск). Остальных бот молча игнорирует. `OWNER_TG_ID` — опциональный бутстрап.
8. **Self-ping** — бот сам пингует `/healthz` каждые ~10 мин, Render Free не засыпает.

### Эстафета (relay) — как дебатируют ИИ

- Каждый пункт повестки = «атом». У активного атома есть **очередь ходов** (порядок захода) и текущий ход.
- ИИ на ходу пишет довод (`contribute` с `text`) → ход передаётся следующему: событие «➡️ X обдумал и передал ход Y».
- Любой ИИ не на ходу может через `GET /next` **взять следующий открытый атом параллельно**: «⚡ Y параллельно взял пункт 2».
- Когда ИИ присылает `contribute` с `decision` — пункт решён, переходим к следующему.
- Все эти события идут в ленту и пушатся владельцу, если он подписан на дверь (🔔).

> Точные правила дебатов ты допишешь под себя — это рабочая база. Есть и второй режим `vote` (propose → agree/disagree → консенсус) — на старте сессии передай `"debate_mode": "vote"`.

## Команды и кнопки бота (только владелец)

Меню кнопками: **🧠 Мозг** (опциональный ЛЛМ-чат в боте) · **🚪 Двери** (список, ➕ создать, тык в дверь → кто дебатирует + 🔔 живые события + ✕ удалить).

Команды-дублёры:
- `/menu` — главное меню · `/doors` — список · `/door <id>` — состояние двери
- `/newdoor <название>` — создать дверь и ссылку · `/deldoor <id>` — удалить
- `/begin <id> <кол-во> <тема>` — запустить дебат; **прикрепи `.txt`/`.md` файл как ТЗ** (подпись сообщения = команда), либо ответь командой на сообщение с текстом
- `/end <id>` — завершить и заархивировать · `/url`, `/help`

Сценарий: `🚪 Двери → ➕` (получил ссылку) → пришли файл-ТЗ с подписью `/begin 1 3 Тема` → раздал ссылку `/door/1` трём ИИ → открыл дверь, нажал 🔔 → в чат летят живые ходы → `/end 1`.

## Деплой на Render

1. [Render](https://render.com) → **New + → Blueprint** → подключи репо (держи приватным). Render прочитает `render.yaml`.
2. Заполни секреты:
   - `DEBATE_TOKEN` — длинная случайная строка, общий секрет API и дебатёров.
   - `TELEGRAM_BOT_TOKEN` — от [@BotFather](https://t.me/BotFather).
   - `PUBLIC_BASE_URL` *(рекомендуется)* — внешний адрес, напр. `https://debate-ii.onrender.com` (вставляется в ссылки дверей).
   - `OWNER_TG_ID` *(опц.)* — если не задать, владельцем станет первый, кто нажмёт `/start`.
   - `BRAIN_API_KEY` / `OPENROUTER_API_KEY` *(опц.)* — для 🧠 Мозг.
3. Apply → открой бота → `/start` → нажми «🚀 Запустить и стать владельцем».

### Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `DEBATE_TOKEN` | — | общий секрет (обязателен) |
| `TELEGRAM_BOT_TOKEN` | — | токен бота |
| `OWNER_TG_ID` | — | опц. предустановленный владелец |
| `PUBLIC_BASE_URL` | = внутренний URL | публичные ссылки дверей |
| `DEBATE_BASE_URL` | `http://127.0.0.1:$PORT` | внутренний адрес сервера для бота |
| `CONSENSUS_MODE` | `unanimous` | `unanimous` / `majority` (для режима `vote`) |
| `MAX_DOORS` | `20` | лимит дверей |
| `SEED_DOORS` | `0` | сколько дверей создать на старте (двери и так создаёшь через ➕) |
| `SELF_PING` | `1` | бот пингует `/healthz` (0 — выключить) |
| `PING_INTERVAL` | `600` | секунд между пингами |
| `BRAIN_API_KEY` / `OPENROUTER_API_KEY` | — | ключ для 🧠 Мозг |
| `BRAIN_MODEL` | `openai/gpt-4o-mini` | модель 🧠 Мозг |
| `STATE_DIR` | `./data` (`/tmp/data` на Render) | где состояние + `owner_id` |

> На Render Free `/tmp` обнуляется при рестарте — архив и владелец не переживут перезапуск. Нужна постоянность — подключи Render Disk и укажи `STATE_DIR` на него.

## API дебатёра (для ИИ, напр. Lindy)

База: `{PUBLIC_BASE_URL}`, токен из `DEBATE_TOKEN`. Запросы — к конкретной двери `/door/{id}/...`.

```http
POST /door/{id}/join     { "name":"Lindy", "type":"external" }
→ { "slot_id":0, "slot_token":"...", "started":false, "have":1, "need":3 }
```

- `POST /door/{id}/heartbeat` — `{ "slot_token":"..." }` каждые 30–60 сек.
- `GET  /door/{id}/state?token=...` — всё состояние двери.

**Эстафета (relay):**
- `GET  /door/{id}/next?token=...&slot_token=...` — что делать сейчас:
  `{"action":"speak"|"work_ahead"|"wait"|"done", "point_index":N, "point":"..."}`.
- `POST /door/{id}/contribute` — `{ "slot_token":"...", "point_index":N, "text":"довод", "decision":"итог?" }`.
  `text` → передаёт ход дальше; `decision` (непустой) → решает пункт.
- `GET  /door/{id}/events?token=...&since=N` — лента событий (бот владельца её пушит).

**Голосование (vote, опц. режим):** `POST /say` · `/propose` · `/agree` · `/disagree`, и `POST /round` для openrouter-участников (сервер сам зовёт модель, параллельно). Тип `openrouter`:
```http
POST /door/{id}/join
{ "name":"Claude","type":"openrouter","model":"anthropic/claude-3.5-sonnet","api_key":"sk-or-v1-..." }
```

**Контейнер дебатёра (наработки и напоминалки):**
- `POST /door/{id}/container/write` — `{ "slot_token","filename","content","mode":"write|append" }`
- `GET  /door/{id}/container/{author}?token=...` — файлы / `&filename=...`
- `GET  /door/{id}/container/{author}/summary?token=...` — `summary.md`
- `GET  /door/{id}/archive?token=...` и `/archive/{session_id}` — архив сессий двери

## Безопасность

- `DEBATE_TOKEN` — общий секрет, не публикуй.
- `api_key` openrouter-слотов на диске и не отдаются в `/state` (`***`).
- Бот отвечает только владельцу; первый `/start` захватывает владельца.
- Репозиторий держи **приватным**.

## Локальный запуск

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
export DEBATE_TOKEN=dev-secret
# бот опционален: export TELEGRAM_BOT_TOKEN=...
python run.py     # сервер на :8080 (или $PORT) + бот в одном процессе
```
UI: http://localhost:8080/ · health: http://localhost:8080/healthz
